# 数据备份与恢复功能实现计划

## 概述

为 RelWatch 提供手动数据备份与恢复功能。用户可在设置页面中一键导出当前数据库到指定位置，或从之前备份的文件恢复数据。采用 SQLite 原生备份机制实现，无需重启应用。

## 期望的最终状态

1. 用户在「设置 → 常规」中可以看到「导出备份」和「导入恢复」按钮
2. 点击「导出备份」→ 弹出系统保存对话框 → 选择路径 → 生成完整的 `.db` 备份文件
3. 点击「导入恢复」→ 弹出文件选择对话框 → 选择备份文件 → 确认后数据恢复 → 提示成功
4. 恢复过程不丢失当前连接，无需重启应用

## What We're NOT Doing

- ❌ 不实现自动定时备份
- ❌ 不实现选择性表导出/导入
- ❌ 不实现备份文件加密（SQLite 文件本身无加密，用户可自行加密）
- ❌ 不实现云端备份同步
- ❌ 不实现备份历史管理和版本对比

## Phase 1: Rust 后端 — 备份/恢复命令

### 概述

#### 2. 新建备份命令模块
**File**: `src-tauri/src/commands/backup.rs`（新文件）
**Changes**: 实现 `export_backup` 和 `import_backup` 两个命令。

```rust
use r2d2::Pool;
use r2d2_sqlite::SqliteConnectionManager;
use rusqlite::backup::Backup;
use std::time::Duration;
use tauri::Manager;
use tauri_plugin_dialog::DialogExt;

use crate::db;

#[tauri::command]
pub async fn export_backup(app: tauri::AppHandle) -> Result<String, String> {
    // 弹出保存对话框让用户选择路径
    let file = app
        .dialog()
        .file()
        .add_filter("Database", &["db"])
        .set_file_name("relwatch-backup.db")
        .save_file();

    let path = match file.await {
        Some(p) => p,
        None => return Err("备份已取消".to_string()),
    };

    let path_str = path.as_path().unwrap().to_string_lossy().to_string();

    // 获取数据库连接并执行 VACUUM INTO
    let state = app.state::<crate::types::AppState>();
    let conn = state.db.get().map_err(|e| format!("无法获取数据库连接: {}", e))?;

    // 先执行 WAL checkpoint 确保数据完整
    conn
        .execute_batch("PRAGMA wal_checkpoint(TRUNCATE);")
        .map_err(|e| format!("WAL checkpoint 失败: {}", e))?;

    // VACUUM INTO 创建一份紧凑的独立副本（SQLite 3.27+）
    let escaped = path_str.replace('\'', "''");
    conn
        .execute_batch(&format!("VACUUM INTO '{}';", escaped))
        .map_err(|e| format!("导出备份失败: {}", e))?;

    Ok(path_str)
}

#[tauri::command]
pub async fn import_backup(app: tauri::AppHandle) -> Result<(), String> {
    // 弹出文件选择对话框让用户选择备份文件
    let file = app
        .dialog()
        .file()
        .add_filter("Database", &["db"])
        .pick_file();

    let path = match file.await {
        Some(p) => p,
        None => return Err("导入已取消".to_string()),
    };

    let path_str = path.as_path().unwrap().to_string_lossy().to_string();

    // 验证文件是有效的 SQLite 数据库
    let header = std::fs::read(&path_str).map_err(|e| format!("无法读取文件: {}", e))?;
    if header.len() < 16 || &header[..16] != b"SQLite format 3\0" {
        return Err("所选文件不是有效的 SQLite 数据库".to_string());
    }

    // 打开备份文件作为独立的 SQLite 连接
    let src_conn = rusqlite::Connection::open(&path_str)
        .map_err(|e| format!("无法打开备份文件: {}", e))?;

    // 获取运行中的数据库连接
    let state = app.state::<crate::types::AppState>();
    let dst_conn = state.db.get().map_err(|e| format!("无法获取数据库连接: {}", e))?;

    // 先清空现有数据，避免主键冲突（按外键顺序删除）
    dst_conn
        .execute_batch(
            "DELETE FROM notification_state;
             DELETE FROM releases;
             DELETE FROM sources;
             DELETE FROM logs;
             DELETE FROM app_settings;",
        )
        .map_err(|e| format!("清空数据失败: {}", e))?;

    // 使用 rusqlite backup API 将备份文件内容复制到运行中的数据库
    let backup = Backup::new(&src_conn, &dst_conn)
        .map_err(|e| format!("创建备份会话失败: {}", e))?;

    backup
        .run_to_completion(100, Duration::from_millis(250), None)
        .map_err(|e| format!("恢复数据失败: {}", e))?;

    Ok(())
}
```

## 注意事项

- `VACUUM INTO` 需要 SQLite 3.27+（bundled 版本满足此要求）
- 导入时先清空再恢复，确保主键和外键一致性
- rusqlite backup API 是默认模块，无需额外 feature 标志
- WAL checkpoint 在导出前执行，确保导出的数据包含所有已提交事务
